# Make CLI dependency resolution and clean installs reproducible

Ensure the project declares the packages it imports directly and resolves a tested CLI framework version in fresh consumer environments. Current metadata requests an unsupported Typer extra, imports `aiohttp` only through a transitive dependency, and permits untested framework upgrades that can change command registration, help rendering, and option behavior. A lockfile alone is not sufficient because package consumers resolve from project metadata.

This work establishes a reliable installation baseline for subsequent safety and command-surface changes.

## Design

Replace `typer[all]` with plain Typer and declare `aiohttp` as a direct runtime dependency. Use the currently verified Typer minor line as the initial supported range: `typer>=0.27.1,<0.28`. Do not add or constrain Click unless the selected Typer distribution actually resolves and supports it; current Typer releases do not install Click as a dependency.

Review all production imports, runtime dependencies, lower bounds, extras, and upstream compatibility constraints. Regenerate `uv.lock` using the repository-standard workflow and verify it against project metadata.

Add explicit Python 3.12 and 3.13 CI coverage. Add a clean-install smoke target that builds the wheel, creates an environment outside the source checkout, installs the wheel with dependencies resolved only from wheel metadata, and invokes both console entry points. The smoke test must not succeed through source-tree imports or preinstalled development dependencies.

Keep unrelated dependency upgrades and feature work out of this ticket.

## Key Decisions

- **Plain Typer, no obsolete extra.** Current Typer publishes no `all` extra, and clean wheel installation reproduces a warning for it.
- **Bound the pre-1.0 framework line.** `>=0.27.1,<0.28` limits untested behavior changes while allowing compatible patches; widening the range requires the same compatibility suite.
- **Do not assume Click is part of the stack.** Compatibility criteria follow resolved package metadata rather than a historical Typer/Click pairing.
- **Test the consumer artifact.** Source-checkout tests cannot prove that wheel metadata is complete.

## Acceptance Criteria

- [ ] Every directly imported third-party runtime package is declared as a direct runtime dependency; in particular, `aiohttp` is no longer available only transitively.
- [ ] Project metadata uses plain `typer>=0.27.1,<0.28` and requests no unsupported Typer extra.
- [ ] No direct Click constraint is added unless production code or the selected Typer package directly requires it and compatibility evidence is documented.
- [ ] Fresh dependency resolution and wheel installation emit no missing-extra or dependency-conflict warnings attributable to project metadata.
- [ ] `uv.lock` is regenerated and `uv lock --check` passes.
- [ ] CI explicitly runs supported verification on Python 3.12 and 3.13.
- [ ] An external clean environment installs the built wheel using its published dependency metadata and runs `monarch --help`, `monarch --version`, `monarch-cli --help`, and `monarch-cli --version` successfully.
- [ ] The wheel smoke test is isolated from the repository source path and development environment.
- [ ] Framework-sensitive tests verify that root help contains all registered command groups, nested help contains representative commands, and representative global options, nested options, list arguments, and error paths parse without warnings or tracebacks.
- [ ] Compatibility tests run against the lower and upper-resolved patch versions of the declared Typer range, or document why the lockfile currently resolves the same tested version for both checks.
- [ ] The clean-install smoke target is exercised by CI and the repository verification/release workflow rather than only manually.
- [ ] `make verify` and the full non-live test suite pass without manually installing undeclared packages.
