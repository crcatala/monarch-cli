# Polish CLI help output and representative examples

Improve the built-in CLI help so it works as a concise getting-started guide for humans and agent authors. Audit the root, command-group, and high-use command help. This ticket does not add a capabilities manifest; `mc-82kf` owns that, and help metadata should stay consumable by it. Keep the scope to discoverability and guidance; do not change command behavior or safety policy.

## Design

Use Typer docstrings/help metadata and the existing explicit operation metadata where useful, while preserving the supported framework range. Grammar and repository example placement are owned by `mc-hu2c`; this ticket fixes conflicts the help audit finds in help text and docstrings rather than duplicating that sweep. Make help consistent and concise: describe command purpose, required arguments, important options, output modes, and a small number of representative copy/paste examples. Mutation commands should visibly explain that --allow-mutations is a global flag placed before the command path, and explain --dry-run where supported. Read-only commands should identify useful output formats and raw-output caveats where relevant. Authentication/help should point to non-interactive behavior when prompts may occur. Keep detailed conceptual documentation in README/docs rather than duplicating it in every help page. Do not add a capabilities manifest, config-management commands, or network/auth work.

## Acceptance Criteria

- [ ] Root help lists every top-level command group with concise, accurate descriptions and useful global safety/output options.
- [ ] Each command group help lists its commands with descriptions that match current behavior.
- [ ] Representative high-use commands have concise examples covering common read, authentication, filtering/reporting, and mutation/preview workflows.
- [ ] Every current remote-mutation command help clearly states that --allow-mutations is required, shows its required global placement before the command path, and documents --dry-run when supported.
- [ ] Help for commands with format/raw/NDJSON/quiet behavior accurately describes supported output choices and does not imply raw output is a stable normalized contract.
- [ ] Prompting and --non-interactive behavior are discoverable from relevant authentication or prompt-capable help without exposing secrets or requiring a network call.
- [ ] Help remains concise and avoids duplicating the full README/schema/recovery documentation.
- [ ] A test driven by the mutation command inventory from `collect_command_effects` asserts the required `--allow-mutations` placement and `--dry-run` guidance for every current and future mutation command, without depending on framework-generated styling or terminal width.
- [ ] Help generation performs no credential lookup, prompt, network request, or config/session file write; creating the config directory when it does not yet exist is permitted (the root config load currently does this and restructuring it is out of scope).
- [ ] README or command documentation examples found conflicting by the help audit are reconciled; the grammar/placement sweep itself is owned by `mc-hu2c`, and repository verification passes.
