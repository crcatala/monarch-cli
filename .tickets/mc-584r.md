# Add disposable-fixture live mutation contract suite

Provide separately gated live contract coverage for mutation workflows without risking ordinary household data. Read-only live smoke coverage remains owned by mc-vcbk; this ticket owns the disposable-fixture strategy, lifecycle, mutation assertions, and cleanup/recovery contract.

## Design

Build on mc-3437 using a mutation-specific opt-in and marker that can never be selected by the read-only live-test gate. Use only fixtures created by the suite in an explicitly approved test context; never select an arbitrary existing transaction, account, split, attachment, receipt, or other household record. Define which upstream entities can be created safely, how each fixture is uniquely identified, how original state is avoided or restored, and how cleanup failures are surfaced for manual recovery. Start with a minimal representative matrix rather than broad mutation coverage. Every mutation uses shared authorization, retry/ambiguity handling, and mutation-outcome contracts. If the service cannot provide a safely disposable fixture for a workflow, skip it with a documented reason rather than mutating user-owned data.

## Acceptance Criteria

- [ ] Mutation live tests require a dedicated explicit opt-in and marker distinct from MONARCH_LIVE_TESTS and are excluded from normal CI and read-only release checks.
- [ ] The suite refuses to run unless the caller supplies the documented mutation authorization and explicitly approved test context.
- [ ] Tests mutate only records created and uniquely tagged by the suite; arbitrary pre-existing household records are never selected as fixtures.
- [ ] Fixture creation, verification, cleanup, and manual-recovery behavior is documented for every covered workflow.
- [ ] Cleanup runs on success and failure where safe, and cleanup failure produces a sanitized non-success result with sufficient identifiers for manual recovery.
- [ ] Timeouts and disconnects follow shared ambiguity policy and never trigger unsafe automatic mutation retries or blind cleanup.
- [ ] The initial matrix is deliberately small and names each covered mutation; split mutation coverage from mc-hp7w is included only when a safely disposable transaction fixture exists.
- [ ] Workflows without a safe disposable fixture are explicitly skipped and documented rather than tested against user-owned data.
- [ ] Logs and failures redact credentials, financial values, local paths, and unnecessary household data.
- [ ] Tests prove the read-only live gate cannot collect mutation tests and the mutation gate cannot run without all safety prerequisites.
- [ ] Local execution, residual-risk, cleanup, and recovery documentation is complete and repository verification passes.
